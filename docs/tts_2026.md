# 2026 TTS research review

This note reviews every 2026 paper indexed by
[TTS-arxiv-daily](https://github.com/liutaocode/TTS-arxiv-daily) through
2026-08-19. The snapshot was commit `08c586b` on 2026-08-20. All 486 records
were checked against their official arXiv metadata and abstracts.

The source search is intentionally broad, so it also contains ASR, deepfake,
singing, spoken-agent, and audio-visual papers. Topic counts below overlap:

## What Nar should add

1. **Independent ASR evaluation.** Keep Qwen3-ASR for training rewards, but
   report results with a different ASR family. Same-family verification can
   overstate gains, and ASR round trips can hide context-dependent reading
   errors ([2607.08256](https://arxiv.org/abs/2607.08256),
   [2608.10606](https://arxiv.org/abs/2608.10606)).
2. **Best-of-N reliability gate.** Generate two candidates, reject malformed or
   ASR-inconsistent speech, and fall back to four candidates for hard prompts.
   This reached near-zero catastrophic failures across several codec TTS models,
   including Mimi-based systems
   ([2606.18323](https://arxiv.org/abs/2606.18323)).
3. **Component-wise group normalization.** Normalize intelligibility and
   speaker rewards separately inside each prompt group before combining them.
   This prevents a low-variance reward from disappearing
   ([2608.03215](https://arxiv.org/abs/2608.03215)).
4. **Hard-case sampling.** Feed pronunciation failures, truncations, repetitions,
   and long prompts back into GRPO instead of sampling only uniform training
   rows ([2606.23190](https://arxiv.org/abs/2606.23190)).
5. **Naturalness and prosody signals.** ASR, speaker similarity, and duration do
   not cover rhythm, pitch, artifacts, or contextual appropriateness. Evaluate a
   validated multi-dimensional reward model before adding it to training
   ([2602.13891](https://arxiv.org/abs/2602.13891),
   [2605.23261](https://arxiv.org/abs/2605.23261),
   [2601.18438](https://arxiv.org/abs/2601.18438)).
6. **Speaker-drift checks.** Compare embeddings over overlapping windows, not
   only one utterance-level embedding
   ([2604.06327](https://arxiv.org/abs/2604.06327)).
7. **Japanese pronunciation tests.** Add rare readings, kanji polyphony, and
   kana-level CER; use targeted synthetic examples for failures
   ([2606.25369](https://arxiv.org/abs/2606.25369),
   [2606.20137](https://arxiv.org/abs/2606.20137)).

The first four items fit the current neural-codec LM. Items 1 and 2 should be
implemented before adding another training reward, because a reward must not be
its own only evaluator.

## Architecture watchlist

The following ideas are promising but require new pretraining and are not safe
drop-in changes for existing Mimi checkpoints:

- Tokenizers optimized for LM predictability or idempotence:
  [ReLMCodec](https://arxiv.org/abs/2608.08286),
  [LILAC](https://arxiv.org/abs/2608.05727), and
  [CleanCodec](https://arxiv.org/abs/2606.04418).
- Joint tokenizer, LM, decoder, and reward training
  ([2606.09234](https://arxiv.org/abs/2606.09234)).
- Patch-level token compression
  ([TLDR](https://arxiv.org/abs/2606.09019)).
- Alternative decoding order or diffusion-language modeling
  ([2601.08450](https://arxiv.org/abs/2601.08450)).
- A mobile Transformer Mimi decoder
  ([T-Mimi](https://arxiv.org/abs/2601.20094)).

Changing the codec invalidates the current tokenized dataset and checkpoints,
so these belong in a future model generation rather than the current quality
alignment stage.

## GRPO decision

Nar keeps one quality-focused `grpo.yaml`: G=8, constrained 32-codebook actions,
component-wise normalization, Qwen3-ASR CER+NLL, WavLM speaker similarity and
drift, duration, technical quality, and prosody. Emotion/event weights remain
zero until held-out classifiers and listening tests validate them.
